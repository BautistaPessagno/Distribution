# Marketing AGI source review for MarketingOS

Research date: 2026-08-30  
Source basis: official `holy-templar/marketing-agi` repository at commit [`acc56bad8afc297d622530214b01b1ea11421e7d`](https://github.com/holy-templar/marketing-agi/tree/acc56bad8afc297d622530214b01b1ea11421e7d), labeled Marketing AGI v1.2 in the repository. No third-party descriptions were used.

## Executive read

Marketing AGI is a strong specification for marketing reasoning. It is not an application, agent runtime, or campaign system. The repository contains Markdown instructions, templates, and rubrics, with no executable code or dependencies. Its author explicitly chose this constraint. MarketingOS should reimplement the useful ideas as typed domain behavior and use none of it as a runtime dependency. [README](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/README.md) · [contribution rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/CONTRIBUTING.md)

The best parts are the small router, shared brand context, evidence rules, artifact-first outputs, explicit handoffs, concept-level ad analysis, and experiment discipline. The missing parts are exactly what MarketingOS must supply: structured state, source provenance, versioned artifacts, resumable jobs, concurrency control, approvals, scheduling, distribution records, metrics ingestion, and a dashboard. [router](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [analytics](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/analytics.md)

HumanPost should remain the main reference for software-coordinated account warming and distribution work. Marketing AGI should shape the layer that decides what to say, why it might work, what evidence supports it, which artifact to produce, and what test would settle the question. This division is an inference from Marketing AGI's explicit boundary: it diagnoses, prescribes, and may produce assets, but it does not handle credentials or change live campaigns. [shared boundary](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [paid-ads boundary](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/paid-ads.md)

## How the router works

The top-level skill performs three actions. It reads `brand-context.md` from one of three conventional locations, identifies the requested job, and loads only the relevant reference files. Multi-part requests load several modules, while prose jobs always add the slop-pattern check. [router setup and table](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

The routing table is a job-to-capability map, not executable dispatch logic. A host model interprets natural language and follows the table. There is no classifier, typed plan, retry policy, cost estimate, permission check, or guarantee that only the named references enter context. The README's progressive-loading claim describes prompt discipline supplied by the host. [README design principles](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/README.md) · [agent entry point](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/AGENTS.md)

MarketingOS should keep this user-facing simplicity but turn it into a persisted `MarketingRunPlan`. The plan should record the job type, required context, modules, evidence inputs, expected artifacts, approval gates, estimated work, and follow-on jobs. The router should output a plan for inspection before expensive generation or any external action. This is an inference from the repository's routing and chaining rules. [routing and chaining](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

## Brand context and evidence model

The brand template captures the product in plain language, its mechanism and exclusions, the buyer's beliefs and alternatives, an uncopyable positioning claim, category and competitors, allowed proof, voice rules, and legal constraints. The proof section asks for sources and dates. This is a good minimum intake form. [brand-context template](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/brand-context.template.md)

The template is still one untyped Markdown file. It has no stable identifiers, audience hierarchy, provenance object, freshness rule, conflict handling, asset catalog, funnel model, metric definitions, claim approval status, or history. A Connected Project can change after the file was generated, and nothing detects the drift. This is an inference from the template and the setup rule that reads it as the shared context. [template](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/brand-context.template.md) · [setup rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

Marketing AGI's honesty rules are worth making system invariants. Scores must say they are heuristics. The system must not invent proof. Small samples cannot produce declared winners. The analysis must form an independent read before comparing with a user's conclusion. Time-sensitive platform facts require verification. Every report records what could not be determined. [honesty spine](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

The analytics module adds an evidence ladder from controlled experiment to "vibes," then requires one variable, one primary metric, a decision rule, a sample target, and a stop condition before a test begins. Its result contract records what the evidence can and cannot support and the cheapest next observation. [analytics evidence and test rules](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/analytics.md)

MarketingOS should represent these rules with `EvidenceItem`, `ProofClaim`, `SourceRef`, `EvidenceAssessment`, and `Unknown`. A proof claim needs text, source, observation date, owner, allowed channels, legal status, freshness deadline, and supersession history. Generated text may cite only approved claims. Missing support should block publication or render a visible `[NEED: ...]` token, matching Marketing AGI's rule. This domain design is an inference from the honesty and proof requirements. [honesty spine](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [copy proof rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/copy.md)

## Output contracts, artifacts, and handoffs

Marketing AGI consistently asks for the usable artifact rather than a recommendation. Audits include replacement copy. GEO produces revised page blocks and JSON-LD. Copy yields ranked variants and a test contrast. Hooks produce a three-part hook matrix. Paid ads produce concept maps and production briefs. Email writes every message. Social writes posts and cadence. Launch produces a dated plan and asset stack. Positioning records the selected and rejected frame. App-store work writes metadata to exact limits and screenshot briefs. Analytics emits an evidence-quality block. [shared output standard](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [GEO contract](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/geo.md) · [hooks contract](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/hooks.md) · [launch contract](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/launch.md)

Its common chains are explicit: audit to copy, audit to GEO, paid ads to hooks to copy, competitive work to hooks to positioning, positioning to copy to launch, and app-store work to copy. It tells the host to carry evidence forward instead of researching again. [chaining rules](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

The handoffs are prose conventions. There is no typed payload, artifact lineage, source snapshot, stable finding identifier, job dependency, or invalidation rule. A later module can silently reinterpret an earlier finding. This is an inference from the Markdown-only design and the handoff instructions. [contribution rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/CONTRIBUTING.md) · [chaining rules](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

MarketingOS should give every artifact a type, version, source snapshot, authoring run, upstream finding IDs, proof claims, status, reviewer, target channel, and experiment ID. A handoff should pass identifiers, not copied prose. If a brand fact or approved claim changes, the dashboard can then mark affected artifacts stale. This is an inference from Marketing AGI's artifact and evidence-carry rules. [shared outputs and chaining](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

## Mechanisms worth implementing

### Audit, GEO, and search

The audit scores six dimensions with explicit weights, requires positive findings as well as defects, computes a weighted total, and turns high-impact, low-effort findings into specific fixes. Its rubric separates evidence coverage from score and keeps `unknown` distinct from `fail`. [audit workflow](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit.md) · [coverage gates](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit-rubric.md)

The GEO workflow begins with human questions, samples each engine at least three times, separates a brand mention from a domain citation, scores extractability, evidence, entity clarity, corroboration, and machine access, then schedules the same questions for re-measurement. It says citation is non-deterministic and refuses to promise it. [GEO workflow and honesty](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/geo.md)

The engine playbook repeatedly warns that behavior and crawler names change, and that no engine publishes citation rules. It also treats `llms.txt` as cheap hygiene with unproven impact rather than a primary lever. MarketingOS should store engine observations with date, locale, model, query, run count, response, cited domains, and source status. It should not encode the current playbook as permanent truth. [engine caveat and `llms.txt`](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/geo-engines.md)

### Content, social, and launch

The copy flow generates 15 to 20 variants across different angles, scores each through five reader perspectives, rewrites promising candidates, drops weak ones, and runs an anti-slop pass before delivery. It also matches copy to the audience's awareness stage. [copy workflow](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/copy.md) · [awareness and angle taxonomy](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/copy-frameworks.md)

The hook engine grounds ideas in winning ads, reviews, comments, and community language. Each video hook has a visual action, spoken line, and on-screen text that do different jobs. Its diagnostic funnel maps thumbstop, hold, click-through, and conversion rates to different failure stages, and its fidelity ladder raises production cost only after an argument shows evidence. [hook grounding and diagnostics](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/hooks.md)

The social module treats each post as a channel-native artifact, specifies the pre-fold hook, records its job, writes alternate hooks, and connects posts through a repurposing tree. The launch module turns positioning, email, social, page copy, demo, objections, and partner copy into a dated campaign with one metric and named owners. [social output and repurposing](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/social.md) · [launch asset stack](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/launch.md)

### Ads and experiments

Paid-ad analysis groups assets by the argument they make. It maps angle, awareness stage, format, hook, spend, and relative performance, then identifies untested combinations. Its fatigue diagnosis reads CTR, CPM, conversion rate, frequency, and time together before recommending creative changes. [concept classification and coverage](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/paid-ads.md) · [diagnostic table](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/ads-diagnostics.md)

This structure should become `CreativeConcept`, `CreativeExecution`, `AudienceSegment`, `AwarenessStage`, `Hook`, `MetricSeries`, and `Diagnosis`. The distinction between a reusable argument and one rendered asset is especially important because experiment results should update the concept without erasing execution-level differences. This domain design is an inference from the paid-ads taxonomy. [paid-ads model](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/paid-ads.md)

## Scores are decision aids, not facts

Marketing AGI's best scoring behavior is structural. The audit has weighted dimensions, band calibration, caps, evidence coverage, and explicit unknowns. GEO uses named levers and repeat observations. Analytics labels evidence quality. These devices make disagreements inspectable. [audit rubric](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit-rubric.md) · [GEO levers](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/geo.md) · [evidence ladder](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/analytics.md)

Its weak scoring behavior is false comparability. Copy's five panel scores are model judgments. Audit band adjustments and automatic caps are authored heuristics. Paid-ad expected-value rankings do not define a formula. Positioning hypotheses do not have market evidence until tested. A polished `86/100` can look more measured than it is, even when the report calls it heuristic. [copy panel](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/copy.md) · [audit caps](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit-rubric.md) · [positioning honesty](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/positioning.md)

MarketingOS should version each rubric and retain criterion-level evidence. It should display score, evidence coverage, confidence, and measured outcomes separately. Heuristic scores may prioritize review. Only experiments and observed business metrics may claim performance. This recommendation follows the repository's own warning that scores are marketing judgment, not measured results. [shared honesty rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

## Connected Projects through MCP

MarketingOS should never read KeepAnalog, partnr, or VinylOS repositories directly. Each Connected Project owns an MCP server. The integration adapter asks that server for a versioned marketing snapshot and translates it into MarketingOS domain objects. The marketing domain depends on a `ConnectedProjectContextPort`, not on the MCP SDK, transport, repository layout, framework, or file paths. This design is an inference from Marketing AGI's shared-context requirement, adapted to the user's MCP boundary. [brand-context requirement](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

The MCP contract should expose semantic resources:

- `project://profile` with product facts, exclusions, lifecycle stage, public URLs, locales, and category. These map to the product section of Marketing AGI's brand context. [template](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/brand-context.template.md)
- `project://audiences` with segments, belief state, problem, alternative, desired outcome, and evidence for each statement. Marketing AGI treats belief state and alternatives as inputs to copy and positioning. [template](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/brand-context.template.md) · [copy intake](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/copy.md)
- `project://brand` with positioning, voice, vocabulary, visual assets, legal constraints, and forbidden claims. [template](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/brand-context.template.md)
- `project://proof` with claim text, source, date, allowed use, and approval state. Marketing AGI forbids invented proof and asks for dated sources. [honesty rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [template](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/brand-context.template.md)
- `project://funnel` with named steps, public pages, conversion events, and metric definitions. The audit and analytics modules reason about activation paths and decision-relevant metrics. [audit dimensions](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit.md) · [test design](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/analytics.md)
- `project://changes` with releases, pricing changes, new proof, and invalidated claims since a cursor. Launch and time-sensitive guidance require current facts. [launch intake](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/launch.md) · [verification rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

Every snapshot needs `project_id`, schema version, source revision, generated time, valid-through time, and per-field provenance. MarketingOS stores the snapshot used by each run. It never reaches through MCP for arbitrary repository files from inside its strategy logic. If the contract lacks required context, the run creates a visible `ContextGap` instead of guessing. This recommendation adapts Marketing AGI's explicit gaps and evidence rules. [gaps and honesty](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

## Smallest useful dogfood MVP

The MVP should ship four native modules and one shared foundation. This is enough to create useful work for all three products without pretending the system already runs a marketing department.

### 1. Connected Project context and evidence foundation

Implement MCP connection, context snapshots, `BrandProfile`, `AudienceSegment`, `ProofClaim`, `Funnel`, `MetricDefinition`, `ContextGap`, artifact lineage, and approval status. All later modules depend on this foundation, just as every Marketing AGI module depends on brand context. [setup rule](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

Dogfood examples: KeepAnalog can expose its demand hypothesis and waitlist path; partnr can expose its ideal client, demo funnel, and approved proof; VinylOS can expose its catalog, activation events, public pages, and allowed user outcomes.

### 2. Positioning and strategy workbench

Implement competitive alternatives, unique attributes, best-fit segment, category frame, offer, rejected alternatives, confidence, and requested evidence. Positioning sits upstream of copy, ads, and launch in Marketing AGI, and it produces the shared context those modules need. [positioning inputs and cascade](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/positioning.md)

Dogfood examples: KeepAnalog needs a demand hypothesis before broad distribution; partnr needs an uncopyable service or product frame for qualified demos; VinylOS needs clear category language for collectors and a reason to return.

### 3. Opportunity audit with SEO and GEO

Combine the six-dimension audit with question-based GEO measurement and a small native SEO layer. The added SEO layer should inventory pages, query intent, indexability, structured data, internal links, and refresh opportunities because Marketing AGI does not cover technical SEO deeply. [audit workflow](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit.md) · [GEO workflow](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/geo.md) · [GEO scope limit](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/geo.md)

Dogfood examples: KeepAnalog can test whether its public story earns waitlist intent; partnr can audit service pages for buyer questions and demo conversion; VinylOS can find collection and discovery pages that deserve search and answer-engine content.

### 4. Artifact studio for content and campaigns

Implement briefs, wide variant generation, awareness and angle coverage, proof enforcement, copy review, anti-slop lint, channel rendering, and approval. Start with landing-page copy, SEO article briefs and drafts, LinkedIn, X, and launch assets. Keep email and paid-ad production behind capability flags until a project has the list, spend, and measurement baseline to use them. [copy pipeline](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/copy.md) · [social output](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/social.md) · [launch stack](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/launch.md)

Dogfood examples: KeepAnalog can produce a problem-seeding arc and waitlist page; partnr can produce founder posts, case-study drafts, and demo-page variants; VinylOS can produce collector stories, searchable collection guides, release notes, and referral prompts.

### 5. Experiment and learning loop

Implement a hypothesis, one primary metric, decision rule, target sample, stop condition, evidence level, result, and cheapest next observation. Connect observations to the exact artifact and context snapshot that produced them. [analytics contract](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/analytics.md)

Dogfood examples: KeepAnalog can compare demand messages by qualified waitlist conversion; partnr can compare positioning angles by qualified demo requests; VinylOS can compare discovery content by organic activation and retained usage, not impressions alone.

Account slots, account instances, warming work orders, operator queues, proof of completion, account health, replacement, and distribution events belong beside these modules in the dashboard. Their behavior should come from the HumanPost research, not Marketing AGI, which has no warming workflow. Marketing AGI contributes the approved artifact, audience, campaign hypothesis, and measurement plan that each work order consumes. The absence of warming behavior is confirmed by the official module inventory. [module directory](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md)

## Native services and dashboard

The MVP needs these services:

- `ProjectContextSync` fetches and validates MCP snapshots, records provenance, and raises gaps.
- `MarketingRouter` produces a persisted run plan from a user goal and available context.
- `EvidenceService` approves claims, checks freshness, and blocks unsupported copy.
- `StrategyService` manages positioning and opportunity hypotheses.
- `AuditService` runs versioned rubrics and retains criterion evidence.
- `ArtifactService` generates, versions, scores, lints, and traces variants.
- `ExperimentService` registers tests before launch and evaluates incoming observations.
- `ApprovalService` enforces human review before any external action.
- `DistributionOperations` creates HumanPost-informed warming and publishing work orders for the sole operator now, with assignments ready for collaborators later.

These services are a product design inference from the source's router, shared context, artifacts, honesty rules, module chains, test discipline, and human-execution boundary. [router and standards](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [analytics](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/analytics.md) · [paid-ads boundary](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/paid-ads.md)

The dashboard should have a project switcher and context-health view, an opportunity and audit view, a strategy workbench, an artifact studio with source and proof inspection, a campaign timeline, an approval inbox, warming and publishing queues, and an experiment results view. Scores should never appear without coverage and evidence quality. This UI follows the native objects above and adapts Marketing AGI's report contracts into persistent work areas. [report skeleton](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/SKILL.md) · [coverage gates](https://github.com/holy-templar/marketing-agi/blob/acc56bad8afc297d622530214b01b1ea11421e7d/skills/marketing-agi/references/audit-rubric.md)

## Recommendation

Use Marketing AGI as the reasoning grammar of MarketingOS, not its engine. The first release should turn its context, evidence, artifacts, rubrics, and handoffs into durable objects around an MCP-only Connected Project boundary.
